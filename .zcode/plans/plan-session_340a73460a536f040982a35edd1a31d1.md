# 云端 AI 强度提升 · 方案 3+5（max_completion_tokens 10K）实施计划

## 背景
已完成 1（分游戏规则）+2（历史12步）+4（允许思考后出JSON），现中国象棋仍有昏招，复盘日志显示 `completion=2048` 已打满且 `fallback extraction` 生效。用户授权不计成本，`max_completion_tokens` 放宽至 10K，需补上：
- **3 带解释的候选**：每个 `legalMoves` 附 `captureValue/givesCheck/localEval` 等提示
- **5 少传冗余多传信号**：补充 `materialDiff/inCheck/威胁摘要/FEN 式精简盘面` 等信号，让大模型做“选择器”而非“计算器”

## 目标
三棋（五子·象棋·国际象棋）云端落子强度显著提升，日志可观测 `prompt/completion`，不破坏现有 `isGomokuState/isXiangqiState/isChessState` 校验与 1小时 TTL 持久化。

## 非目标
- 不引入向量库/RAG、不训练/微调基座模型
- 不改动 `supabase/schema.sql` 表结构

## 分步执行与验收

### Step 1 — 修复 Edge 回传 bug（1h）
改 `index.ts:211-214`：`ProviderResult` 已有 `move`，实为丢弃 `result.usage`，导致 handler 前端 `data.usage` 恒 undefined。让 `basetenProvider.request` 返回 `{provider,model,move,usage}` 并透传。
- **验收**：任意一棋落子，Edge 日志出现两行 `baseten usage prompt=...` 且浏览器控制台出现 `[game-ai] usage game=...`；`finish_reason=length` 仍不抛 502。

### Step 2 — 前端提示生成器（每棋独立文件，<150行）
各新增 `cloudHints.ts` 暴露 `buildCloudHints(state, legalMoves) → {annotatedMoves, threatSummary}`：
- **Gomoku**：对每个 `{r,c}` 计算 `isWinningMove/isBlockingWin/threatScoreSelf(threatScoreOpp)/totalLocalScore/centerDistance`（复用 `findWinLine` + `potential`，O(121) 1-ply，无深度搜索）
- **Xiangqi**：`captureValue(PIECE_VALUE)/givesCheck(inCheck)/givesMate(isCheckmate)/materialDiff(evaluate delta)/hangsPiece(pressure)/mobilityAfter`（复用 `evaluate.ts:30,15` 与 `logic.ts:238,259`）
- **Chess**：`captureValue(VALUE)/givesCheck/givesMate/isEnPassant/isCastling/isPromotion/localEval/shallowScore(evaluate)/repetitionRisk(positionHistory)`（复用 `ai.ts:7` 与 `logic.ts:48,77`）
- **验收**：三 `cloudHints` 单测：空盘与中盘各一例，`annotatedMoves.length === legalMoves.length`，关键字段非空，计算耗时 <30ms/次。

### Step 3 — 前端注入 position（3处各+2行）
`position = {board, turn,..., history: moveHistory.slice(-12), threatSummary, hints: annotatedMoves.slice(0,60)}`（超 200 个候选截断，edge 已有 200 校验）。
- 向后兼容：`history` 为空数组时服务端 `historyHint` 为空串；`isXState` 校验仅查 `board/players/status`，新增键不被拒。
- **验收**：Network 面板 `functions/v1/game-ai-move` 请求体含 `threatSummary` 与 `hints` 数组；老存档回放不报错。

### Step 4 — Edge 提示词升级 + 10K 上限
- `max_completion_tokens: 4096 → 10000`，`temperature: 0.2` 保持，系统消息改为 `Think concisely in mind (2-4 sentences max) ... then ONLY JSON`（由 1-3 放宽，配合 10K 允许更深分析），用户消息追加 `\nThreats: ${threatSummary}\nAnnotatedLegalMoves: ${JSON.stringify(hints)}\n`（与现有 `RecentMoves` 并列）。
- 同步修 `opencode` 分支 `instructions/input` 加入同字段。
- **验收**：象棋开局 `prompt ~1500 completion 400-900`，不再出现 `completion=4096` 打满；Edge 日志 `Using provider=baseten` 旁 `threatSummary` 非空；1次 `completion=10000` 打满需触发告警日志。

### Step 5 — 联调与回退保障
- 保留 `parseJsonObject` + `candidate exact match` + `[r,c]` 正则坐标兜底；新增 `threatSummary` 文本中的坐标不污染兜底（用 `AnnotatedLegalMoves:` 标记段分隔）。
- **验收**：手动构造“模型只吐推理不吐JSON”响应，`attempting fallback extraction` 仍能在 90% 案例命中；三棋各走 20 手无 `502` 雪崩，全回退到本地 AI 时游戏不卡死。

### Step 6 — 质量门
- `npm run lint && npm run build` 通过
- 每棋 200 行上限检查：新 `cloudHints.ts` 各自 <150 行，`index.ts` 合并后约 260 行需拆 `providers/types` 回独立文件或接受单文件例外（已因打包问题单文件化，需在注释说明）
- 线上验证：三棋各开一局，确认 Edge 日志 `usage` 与浏览器 `usage` 一致，`fallback extraction` 占比 <20%

## 风险与缓解
- **Hint 体积过大 → 超 200 截断/prompt 膨胀**：前端截断 60 步、服务端 `JSON.stringify` 后超 4k 字符再截断 + 打 `warn`
- **本地评估耗时**：象棋 `evaluate` 含 `pseudoMoves` 90格扫描，实测 <5ms，可接受；若卡顿则降级为 `captureValue+givesCheck` 极简版
- **提示词泄露坐标污染兜底**：兜底正则前先尝试 `parsed.move` 精确匹配，再尝试 `AnnotatedLegalMoves` 段内匹配，最后才全文扫坐标
