# 本地消息 Reaction 实施计划（精简版 · 用户已确认）

## Context
用户确认：仅需把「与助手的聊天消息」和「MUD 游戏卡片消息本身（`__GAME__:mud:world` 所在的那条私聊消息）」作为本地消息处理，支持 reaction 并持久化到本地；MUD 的游玩/世界状态等联网逻辑保持不变。

现状：
- 私聊已本地化：`companionStore.ts` → IDB `companion_messages`，`App.tsx` 合并为 `ChatEntry` 展示，含 MUD 卡片（`triggerWorldMudCard` 创建的 `createUserCompanionMessage`）。
- Reaction 仅走远端 `chat_reactions` 表（`chatReactionRemote.ts` + Realtime），私聊 id 无云端行，点表情无法落库。
- MUD 游戏逻辑（`WorldMudGame.tsx` / `worldState.ts` / `worldMudNarrate.ts`）保持联网，不改动。

## 实施内容

### 1. `src/lib/idb.ts`
- `DB_VERSION 3→4`，新增 `LOCAL_REACTIONS_STORE='local_reactions'`（keyPath `id`，`id = ${messageId}:${userId}:${emoji}`）。
- `onupgradeneeded` 兼容创建，不影响旧表。

### 2. 新增 `src/lib/localReactions.ts` (<200 行)
- 定义 `LocalReactionRecord { id, messageId, userId, emoji }`。
- 提供 `localReactionId(...)`、`loadLocalReactions()`、`saveLocalReaction()`、`removeLocalReaction()`、`removeLocalReactionsForMessage(messageId)`、`loadLocalReactionRows 的封装`。
- 复用 `chatReactions.ts` 的 `applyRoomReactionChange / summarizeRoomReactions` 类型，不复制表情常量。

### 3. `src/App.tsx` 改造（核心）
- 新增 state `localReactionRows: RoomReactionRecord[]`，启动与 companion 同步加载 `loadLocalReactions()`。
- 构造合并后的 reactions：`localReactionState = summarizeRoomReactions(localReactionRows, selfId)` → `mergedReactions = { ...room.reactions, ...localReactionState }` 传给 `MessageList`。
- `handleLocalReact(messageId, emoji)`：计算 `active`，乐观更新 `localReactionRows` via `applyRoomReactionChange`，调用 `saveLocalReaction/removeLocalReaction` 持久化，记录 `recordEmojiUse`，失败回滚；并处理 `recordInteraction` 统计。
- `onReact` 分发：`privateIds.has(id) ? handleLocalReact : room.toggleReaction`。
- `onRemove` 清理：本地消息删除时同步 `removeLocalReactionsForMessage(id)`；profile 过期 / summary 完成时 `clearCompanionMessages` 同时 `idbClear(LOCAL_REACTIONS_STORE)`。
- 定时与启动时 `pruneLocalReactions`：删除已无对应本地消息的悬挂 reaction（传入当前 `privateIds`）。

### 4. 文档与校验
- `npm run build` 与 `npm run lint` 通过。
- 验证路径：私聊消息与 MUD 卡片消息上悬浮表情/菜单表情/已有点赞胶囊均可切换，刷新后仍在，删除消息后对应 reactions 消失；云端普通消息 reactions 仍走 Supabase 不受影响。
